# Setting a Machine Up from the URL Alone

Date: 2026-09-22
Schema: Construct 3 r495.2

## Problem

A user new to Git gives an agent the address of this repository and nothing
else: no clone, no game project, often no instruction file. With a harness
that has a shell, the agent can clone; what it lacks is a place that tells
it what to clone and what to run afterwards.

What the agent meets today is the README, whether it fetches the GitHub page
or clones and reads the folder. The README's instructions for agents sit in
its fifth section, after the data tables, and start from a clone and a
project that already exist. `install.py` stops when it finds no
`project.c3proj`, nothing fetches `Construct3-Manual`,
`Construct-Example-Projects` or `Construct-Addon-SDK`, and the block those
clones are named in expects them beside this repository. A small model does
not assemble the four clones and the install from that prose; the skill
evaluations of `project-tools-skill.md` showed the same models following a
command block they were given and skipping a row of a table.

## Decision

- The README opens with a section of two commands: clone this repository,
  then `python Construct3-RAG/scripts/bootstrap.py --project MyGame`. Both
  READMEs carry it, before the data.
- `scripts/bootstrap.py` clones the three repositories beside this one when
  they are missing, `Construct-Example-Projects` with `--depth 1` (its
  history is 475 MiB packed; one commit is what the skill reads), creates
  the project folder when it does not exist, and hands over to the skill's
  `install.py`. It is idempotent: a clone present is left as it is, and the
  install refreshes. Without Git it says what to install or download, per
  repository, and exits 1.
- The empty project is not stored here. It is the project the editor saves
  for File > New, kept as its own repository,
  `XHXIAIEIN/Construct3-New-Project`, so that the editor's release, not this
  repository's, decides its contents; the user refreshes it by saving a new
  project over it. `bootstrap.py` clones it only when a project is to be
  made, copies it without `.git`, and gives the copy the folder's name and
  a fresh `uniqueId` of the editor's shape. It contains no scripts folder
  and no TypeScript setup: `scripts/ts-defs` is derived from the project's
  own objects and layouts and regenerated by the editor, the template's
  `.gitignore` already excludes it, and a script file added by hand is
  invisible to the editor until `project.c3proj` lists it. A project that
  needs scripting gets it from the editor's Scripts menu once.
- `install.py` writes the line `@AGENTS.md` into `CLAUDE.md`, creating the
  file when the project has none, when it writes the block. Until now it
  only said that the line was needed; a novice does not act on that.
  An instruction file that already names the clone is still left alone.

## Verified

`tests/test_project_tools.py`: the project is created from a template
folder with its own name and id and the skill installed in it; a second run
changes nothing and fetches nothing; a folder with files that is not a
project is left as it is; `--dry-run` names the four clones it would make
and writes nothing; the template is cloned from a local repository given
as a URL. Run live against the editor's r495.2 empty project on this
machine: the created project passes `check_project.py` (`ok: 0 object
types, 0 families, 1 layouts, 1 sheets`).

## Not verified

- The template repository's address: the folder exists locally and is not
  yet pushed. `--template <folder|url>` overrides the default.
- A small model starting from the URL alone in a harness with a shell. The
  section is written for it; the run is not done.
- The created project opened in the editor. The checker applies the
  editor's load rules for what it covers; the editor was not started.
- A clone over a slow connection: `Construct-Example-Projects` is 744 MB
  checked out even shallow. `--no-examples` skips it; the block's table row
  for official examples then leads nowhere until it is cloned.
