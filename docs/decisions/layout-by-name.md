# Layout by Name: Components, Bands and Computed Checks

Date: 2026-10-06
Schema: Construct 3 r495.2

## Problem

A text-only model that writes a small demo as a spec for the generator
template's helpers wrote every placement as numbers: columns, rows and sizes.
The demos it built read badly in measured ways. The one object a demo is about
covered a fifth of the screen's width in an empty screen. Labels sat at
arbitrary rows, a title above the top edge, a hint off the middle. A "button"
was a text with nothing under it. A coloured state came out dark, because Set
color multiplies a grey image. A pop-up menu never built: its labels over its
buttons were refused as text over a shape, nothing in the spec said "this text
is that button's label", and the refusal named one problem a run, so each fix
met the next refusal until the run ran out of steps.

Task: the builder decides the look, and the model only picks names. The
default path calls it: a game generated by the template, and any spec builder
written on the template's helpers, such as the one of a chat bot outside this
repository.

## Evidence

The method: the model chooses names (a band, a component, a theme), code
computes every position and size, and code checks the result as numbers. A
text-only model cannot check a screenshot, so every check works on numbers.
Four mechanisms carry it:

- A component that cannot be split: a button always has its text, drawn in
  the same box.
- A screen of fixed, named bands, and a main object that fills a share of its
  band.
- All the errors of a layout in one report, the lossless ones fixed by code,
  each remaining one with the one value to write.
- Measured checks: text inside the screen, text over a shape it does not
  belong to, a tapped object smaller than a finger, the declared main object
  outshone by another (area times contrast with the background).

The numbers with a source are the touch target (44 pt on iOS, 48 dp on
Android, WCAG 2.5.5) and the text contrast of WCAG 2.2, 1.4.3. The share a
main object covers is a starting value, tuned on the demos below.

Ten one-mechanic demo requests were built through such a spec builder with
positions as numbers and with names. Each result was played in the editor's
preview against every clause of the request:

| | Numbers | Names |
|---|---|---|
| Built and sent | 5 of 10 | 10 of 10 |
| Right | 3 | 4 |
| Partly right | 0 | 3 |
| Wrong | 2 | 3 |

With names, every text sits in a named band or on its button, so no title is
cut at the top edge and no label is left beside a button. A toggle shows its
two states as two frames. The wrong results come from event logic, outside
the layout: two triggers on stacked buttons of separate types, a reset on a
fixed beat, a hit with no collision event.

## Options

1. Keep placements as numbers and add refusals. Each refusal names one value,
   but a model that writes positions keeps meeting the next one; the menu
   above did until the run ran out of steps.
2. A model that writes coordinates and a checklist of its own. A text-only
   model does this arithmetic badly, and nothing checks the checklist.
3. Names for parts, positions computed: components, bands and themes, with the
   checks run on the computed boxes.

## Decision

Option 3. The template's helpers:

- `button()` draws a shape and its label as one part. The shape is at least
  `button_size(text)`. The label is centred on it, in the colour `text_on()`
  picks for its fill, at the size `label_size()` gives. The label is the
  shape's child in the layout's hierarchy (`link()`, written as the editor
  writes `sceneGraphData`), so hiding, moving or destroying the button takes
  the label along.
- `labelled_bar()` holds a bar and its name to an edge as one box.
- `bands()` lays a one-screen layout out as a title band, a status line, the
  stage and a hint line, MARGIN inside the viewport. `band_text()` puts a
  label in a band by name, at the body size when the title size does not fit.
  `fit()` sizes the stage's main object to `STAGE_SHARE` of the stage with its
  proportions, and `stage_cell()` centres it.
- `no_overlap()` names every box in the way at once.
- `text_contrast()` asks 4.5:1, and 3:1 from 18 pt, the size WCAG counts as
  large-scale text; its 14 pt bold case is not used. At a 32 px grid the body
  size is 32 pt, so a label there needs 3:1.

A spec builder on these helpers lets a model write a band name, a `label` on a
Sprite, a theme and a frame per state. It makes the lossless fixes itself: a
text placed on a button becomes its label, a text "above" a shape with no room
above goes below it, the one centred shape of a stage grows to `fit()`, an
outline that does not read on the fill is replaced, a label alone in its band
takes the band's width. It refuses Set color on an image that is not white,
since the colour multiplies the image. It refuses buttons that cover each
other exactly, naming the rows of a column and the shift of a partial
overlap. Every remaining layout problem comes in one refusal, each with the
value to write.

## Re-evaluate when

- A request needs a screen the four bands do not hold (a board with a side
  panel, a menu screen): add a skeleton then, not before.
- The demos show a main object too large or too small at `STAGE_SHARE`.
- `text_ems()` and the size measured in the preview disagree enough that a
  band refuses a text that fits, or passes one that does not.
